## 1.4 画面構成

1 画面構成。ヘッダー・メイン領域・フッターの 3 区画。**ヘッダー・フッターは 1 行に収まる高さとし、メイン領域を最大限確保する。**

| 区画 | 内容 |
| --- | --- |
| ヘッダー | アプリケーション名（固定表示。読み込んだファイル名は表示しない）と、「ファイルを開く」ボタン（複数選択可。開くたびに読み込み済みの内容に追加する）・「リセット」ボタン（メイン領域をクリアし読み込み状態を初期化する）を 1 行で配置する |
| メイン領域 | アローダイアグラム。左から右へ時間が進む向きで描画。複数プロジェクトは縦方向に積んで同時表示する（機能仕様書 3.5.4 参照）。各プロジェクトの先頭タスクの上部・左詰めにプロジェクト名を表示する（機能仕様書 3.5.4 参照。孤立タスクの独立プロジェクトには表示しない）。**ズーム操作用の拡大・縮小ボタンを設ける**（具体的な位置・デザインは **【未定】**） |
| フッター | 左端に「担当者凡例」ボタン（4.2.4 参照）・「依存関係編集」ボタン（4.3 参照）・「エラー表示」ボタン（エラー仕様書 5.1 参照）・「休日設定ファイル」ボタン（機能仕様書 3.7 参照）をこの順で配置する。エラー表示ボタンの右側に、エラー件数を丸バッジで表示する（エラー仕様書 5.1 参照）。右端に著作権表示・ライセンス種別・サードパーティライセンスを横並びで表示（全文は表示しない。機能仕様書 7 章参照） |

- エッジ（作業矢線）は担当者ごとに色分けする
- 配色はダークモード基調とし、純白（#FFFFFF）・純黒（#000000）は使用しない
- キーカラーは `#1414A0`（明度調整は行わず、この値をそのまま使用する）
- **主要な操作（ファイルを開く、リセット、休日設定ファイルの読み込み等）は、操作結果を画面に通知する。** 具体的な通知の表現（表示位置・形式等）は **【未定】**

## 4.2.4 レイアウト

座標計算方式（時間軸との対応、交差最小化のアルゴリズム等）は本書の対象外とする。ここでは表示上の要件のみを定める。

| 項目 | 仕様 |
| --- | --- |
| 矢線の描画 | **折れ線。** ただし所要日数が仮置き（機能仕様書 3.6 参照）のタスクは**ジグザグの実線**とする |
| タスク名ラベル | 実作業の矢線の**上にタスク名をテキストで表示する**。ダミー矢線には表示しない |
| 色分け | 実作業の矢線を担当者ごとに色分けする。**色の割り当ては全プロジェクト横断で一貫させる**（機能仕様書 3.5.3）。**固定のパレットは持たず、読み込み済みの全プロジェクトの担当者数に応じて色相環（Hue）を均等分割し、都度動的に生成する。** ファイルの追加・解除で担当者数が変わるたびに再生成される。**色と担当者名の対応は凡例パネルで確認できる**（下記参照） |
| プロジェクト境界 | 複数プロジェクト表示時、**各プロジェクトの領域をグレーの水平線で区切る**（機能仕様書 3.5.4 参照） |
| プロジェクト名ラベル | 各プロジェクトの**先頭タスクの上部・左詰め**にプロジェクト名（ファイル名。拡張子を除く）をテキストで表示する。OS 標準フォント、ダークモード基調の配色（純白・純黒は使用しない）。孤立タスクの独立プロジェクト（機能仕様書 3.5.5 参照）には表示しない |
| ダミー | 破線・無彩色。**合流イベントの直前まで先行タスクの行（レーン）を水平に保ち、末尾だけ斜めにする。** ダミーのみの分岐にも layout がレーンを1本専有させるため、この形で実作業と重ならない |
| クリティカルチェーン | **強調表示は矢線（エッジ）のサイズを大型化することで表現する**（線幅を太くする）。**同着で複数存在する場合（機能仕様書 4.1.3）は代表の1本を横一直線に配置する** |
| クリティカルチェーン以外の分岐 | クリティカルチェーンから分離してから再度合流するまで、**ダミー矢線も含め1つの行を専有する。** 分離してから合流するまでの区間が短い分岐から順に、クリティカルチェーンに最も近い空き行に配置する。**分岐同士は、実際に描かれるアローの水平区間（backboneへ繋ぐダミーを含む）が別タスクと同一行で重ならない限り同じ行を共有する**（重なる場合はより遠い行へ押し出す）。**各分岐の内部でも、最長パス（経路上のタスク数が最多の1本）を1つの行にまっすぐ固定し**、それ以外のフォークはバリセンター法で周囲の行に配置する（分岐した鎖が行をまたいで折れ曲がるのを防ぐ） |
| 複数先行タスクからの合流 | 複数の先行タスクから合流するタスクは、**先行のうち最も上のレーンにある `end` ノードの行に揃えて分岐させる**（他の先行からの斜め線はタスクに重なってよい） |
| 合流バッファ候補 | **強調表示は合流イベント（ノード）のサイズを大型化することで表現する** |
| 操作 | **ズーム・パンに対応する（Google マップの UI と同様のマウスホイール操作・ドラッグ操作）。タスク詳細のツールチップ表示は行わない。横軸の目盛り行は常にビューポート上端に固定し（ヘッダー化）、上下パンでは動かさず、横スクロール・ズームにのみ追従させる（固定クリップ枠の内側要素だけを変形する）。営業日軸のラベルは低ズーム時に重ならないよう間引く（右端の `0` は常に表示）。** |
| プロジェクトを縦積み表示（機能仕様書 3.5.4 案 A）する場合の時間軸 | 横軸は**既定でカレンダー軸**（機能仕様書 4.1.5 参照）。**ヘッダー右端の切り替えボタンで営業日軸表示に切り替えられる**（下記「横軸の表示モード」）。切り替えは表示のみで、ES/LS・クリティカルチェーン・合流バッファの算出結果・AOA のレーン並びには影響しない |
| レーン（行）並び | **軸モード（カレンダー／営業日）に依存しない。カレンダー表示時のレーン並びを正とし、営業日数表示も同一のレーン並びにする。** 今後 layout / render を変更する際もこの不変条件を守る |

**横軸の表示モード：** ヘッダー右端のボタン（カレンダー軸のときは「営業日数表示に変更」／営業日軸のときは「カレンダー表示に変更」＝いずれも切替先を表す。字数差で幅が動かないよう、長い方に合わせて最小幅を固定する）で切り替える。**既定はカレンダー軸**（共通時間軸の原点が定まらない場合は表示だけ営業日軸にフォールバックするが、ボタンのラベルはカレンダー軸を表す「営業日数表示に変更」のまま）。ボタンは、ファイル未読込・リセット直後（プロジェクトが0件）のあいだと、営業日軸モードかつ原点未定でカレンダー軸へ切り替えられないときに無効になる。目盛り行はどちらのモードでもビューポート上端に固定される（上記「操作」）。

- **カレンダー軸（既定）：** 横位置を共通時間軸の原点日付（機能仕様書 4.1.5）を起点にした実カレンダー日に比例させる。**土日祝の分だけ横に隙間が空き**、非営業日の帯を薄く網掛けする。グリッド線は営業日ごとに引き、**日付ラベルは週ごと**（各週で最初に現れる営業日に `M/D`。月が変わる箇所は `M月D日`、年が変わる箇所は `YYYY年M月D日`）。
- **営業日軸：** 目盛りは営業日単位。**最終タスクの終了（右端）を `0` とし、開始方向へ「完了までの残営業日数」を加算した数字を表示する**（表示のみ。ノード位置・グローバル営業日番号・オフセット・W315判定は不変）。土日祝は軸上に存在せず詰まる。
- カレンダー軸の**描画**は共通時間軸の原点日付が決まっている場合のみ可能。全プロジェクトに有効な開始日が1件も無い（W315）とき、既定のカレンダー軸モードのままでも表示は営業日軸へフォールバックする（ボタンのラベルは「営業日数表示に変更」のまま、押下で営業日軸モードへ切替可）。営業日軸モードから戻す「カレンダー表示に変更」ボタンは、原点未定の間だけ無効になる。
- タスク列が示すのは「原点＋その ES 営業日数」で計算した暦日であり、CSV 記載の開始日そのものではない（機能仕様書 4.1.5 注記のとおり）。

**凡例パネル：** 担当者ごとの色分けが、どの担当者を指すか確認できるよう、凡例を設ける。

- フッター左端の「担当者凡例」ボタン（1.4 参照）で開閉する。パネルは通常は折りたたまれている
- 展開すると、**担当者名と、その担当者に割り当てられた色の組み合わせを一覧表示する**（「未アサイン」用の色を含む。機能仕様書 3.6 参照）
- 色相環による動的な色再生成（上記「色分け」参照）が発生するたびに、凡例の内容も追従して更新される

## 4.3 依存関係の手動編集ペイン

機能仕様書 4.3 の操作を行う領域。機能そのものの仕様（対象タスク・追加/削除の意味・出力 CSV の形式等）は機能仕様書 4.3、メッセージ文言はエラー仕様書を参照。ここでは画面上の要素と挙動のみを定める。

| 項目 | 仕様 |
| --- | --- |
| 開閉 | フッター左端の「依存関係編集」ボタン（1.4 参照）で開閉する。通常は折りたたまれている（凡例パネルと同じ挙動） |
| 1 行目 | 対象プロジェクトを選ぶリストボックス。選択肢はファイル単位（孤立タスクの独立プロジェクトは選択肢に出さない）。切り替えると、表の内容と「元に戻す」／「やり直し」の履歴が対象プロジェクトのものに入れ替わる |
| 2 行目 | ボタンを左から「グラフを更新」「変更内容を出力」「元に戻す」「やり直し」の順に配置する。変更が 0 件のとき「変更内容を出力」を無効化する。遡れる履歴がないとき「元に戻す」「やり直し」をそれぞれ無効化する |
| 表 | 3 列 × 対象プロジェクトのタスク数。左＝先行タスク一覧、中央＝タスク一覧、右＝後続タスク一覧。中央列のセルは「(先頭 4 桁 ID)タスク名」で表示する。ペインは横スクロールが生じない幅を確保し、セル内容は折り返す（縦スクロールのみ） |
| 変更マーク | 後続タスク一覧が読み込み時と異なるタスク名を、暗い赤（`#8B0000`）の文字色で表示する（機能仕様書 4.3） |
| 追加の操作 | 中央列のセルを右クリックし、コンテキストメニューから「先行タスクを追加する」または「後続タスクを追加する」を選ぶ。続けて中央列から相手タスクを選択する |
| 選択モード中の表示 | 相手タスクの選択待ちの間、左右の列・リストボックス・全ボタンを操作不可にし、背景を不活性を示す薄いグレーにする。最初に選んだ行の直下に「追加をキャンセルする」行を一時的に表示し、この行または相手タスクの選択でモードを抜ける |
| 削除の操作 | 左列または右列のセルを右クリックし、「タスクを削除する」を選ぶ |
| 表の更新 | 追加・削除・元に戻す・やり直しのたびに表を更新する。アローダイアグラムは「グラフを更新」を押したときのみ更新する |
| メッセージ | 操作拒否（循環・重複・自己参照）、編集内容の破棄確認、レイアウト変動の初回通知は、いずれもモーダルなメッセージウィンドウで行う（エラー仕様書 参照） |
