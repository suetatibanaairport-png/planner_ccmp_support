## 5. エラー処理

### 5.1 方針

- エラーは **致命的エラー** と **警告** に区分する
- **エラーの影響範囲はファイル単位に閉じる。** あるファイルで致命的エラーが発生しても、他のファイルの読み込みと描画は継続する。エラーとなったファイルのみ読み込み対象から除外し、その旨を表示する
- 致命的エラーは、原因と該当箇所（**ファイル名**・行番号・タスク ID）を画面に表示する
- 警告は処理を継続し、該当タスクを図上で識別可能にしたうえで一覧表示する
- オフライン動作要件のため、エラー情報の外部送信は行わない
- **致命的エラーが単発（1 件）の場合は `alert` で表示する。**
- **複数件、または複数ファイルにまたがる場合は、専用のエラー表示パネルに一覧表示する。** パネルは通常は折りたたまれており、フッター左端の「エラー表示」ボタン（機能仕様書 1.4 参照）で展開する。折りたたまれている間も、**ボタン右側に丸バッジでエラー件数を表示する**（エラーが 0 件の場合はバッジを表示しない）
- **パネルの形式：** テキストが縦に連なり、スクロールできる一覧とする。エラー 1 件につき以下の行で構成する。
  - 1 行目：`<ファイル名> - <ステージ名>`（例：`planB.csv - データ整合性`）
  - 2 行目以降：エラーコード・メッセージ等、エラーの内容を 1 行ずつ列挙する
- **ステージ名は、5.2 のエラー分類に対応させる。** `E1xx`＝「ファイル・パース」、`E2xx`＝「データ整合性」、`E4xx`＝「処理」

### 5.2 エラー一覧

#### 5.2.1 ファイル・パース系（致命的）

| ID | 事象 | メッセージの要点 |
| --- | --- | --- |
| E101 | ファイルが CSV として解釈できない | 形式不正 |
| E102 | ヘッダー行が存在しない | 先頭行を確認 |
| E103 | 必須列（タスクID／タスク名／メモ）が存在しない | 欠落している列名 |
| E104 | 文字コードを判別できない／文字化けしている | UTF-8 での再出力を案内 |
| E105 | データ行が 0 件 | 内容が空 |

#### 5.2.2 データ整合性系（致命的）

| ID | 事象 | 対応 |
| --- | --- | --- |
| E201 | **同一ファイル内で**タスク ID が重複している | 該当 ID を表示して当該ファイルを中止。ファイルをまたぐ ID の重複は E206 として別途検出する（機能仕様書 3.5.1, 3.5.6） |
| E202 | タスク ID が空欄の行がある | 該当行番号を表示して中止 |
| E203 | 依存関係に循環がある | **循環経路をタスク ID の順序で表示する**（例：A → C → B → A）。単なる関与タスクの列挙ではなく、経路として特定できる形で示す |
| E204 | 1 タスクのメモ欄に `先行タスク:` が複数回出現している | 該当タスク ID を表示して当該ファイルを中止 |
| E205 | 同一ファイル名のファイルを重複して読み込もうとした | 該当ファイル名を表示し、後から読み込もうとしたファイルの追加を拒否する（機能仕様書 3.5 参照） |
| E206 | 同一のタスク ID が複数ファイルに出現する | 該当ファイル名とタスク ID を表示し、後から読み込もうとしたファイルの追加を拒否する（機能仕様書 3.5.6 参照） |

#### 5.2.3 データ整合性系（警告）

| ID | 事象 | 継続時の扱い |
| --- | --- | --- |
| W301 | `先行タスク` の参照先 ID が存在しない | 当該依存辺を無視 |
| W302 | 自己参照（自分自身を先行に指定） | 当該依存辺を無視 |
| W303 | 同一の先行 ID が重複記載されている | 重複を除去 |
| W304 | 開始日が空欄 | 所要日数を 3 営業日として仮置きし、エッジをジグザグの実線で描画する（機能仕様書 3.6 参照） |
| W305 | 期限日が空欄 | 同上 |
| W306 | 開始日 > 期限日 | 開始日・期限日が空欄の場合と同様に扱う。所要日数を 3 営業日として仮置きし、エッジをジグザグの実線で描画する（3.6, W304/W305 参照） |
| W307 | 日付形式が不正 | 当該タスクを日付欠落として扱う |
| W308 | 所要営業日数が 0（期間内が全て非営業日） | 0 日として継続 |
| W309 | 担当者が空欄 | 「未アサイン」として色を割り当て |
| W310 | `先行タスク` の記載が 1 件もない | 当該ファイルは依存関係がなく図を構成できない旨を通知 |
| W311 | 孤立タスク（先行も後続も持たない） | まとめて独立したプロジェクト（レーン）として図に表示する（機能仕様書 3.5.5 参照） |
| W312 | 定期的＝はい のタスクが含まれている | ネットワークから除外して継続する（対応範囲外のため）。当該タスクを参照していた辺は W301 と同様に無視する（機能仕様書 3.6 参照） |
| W313 | 休日設定ファイルに日付形式が不正な行がある | 当該行のみを無視し、読み込みを継続する（機能仕様書 3.7 参照） |
| W314 | 読み込んだ休日設定ファイルが読み込めない（形式不正等） | 置き換えを行わず、それまで使用していた内容（既定ファイル、または直前に読み込んだファイル）のまま継続する（機能仕様書 3.7 参照） |
| W315 | プロジェクト（または孤立タスクの独立プロジェクト）内に有効な開始日を持つタスクが 1 件もない | 共通時間軸（機能仕様書 4.1.5）の基準日を決定できないため、当該プロジェクトのオフセットを 0（全体の原点上）として継続する。**全プロジェクトが該当する場合は、実日付に基づかない仮想的な原点を用いる**（4.1.5 参照） |

#### 5.2.4 複数ファイル系（警告）

| ID | 事象 | 継続時の扱い |
| --- | --- | --- |
| W353 | 列構成が他のファイルと異なる | 当該ファイル単独で判定して継続する |
| W354 | 読み込み可能なファイルが 1 件もなくなった（全ファイルが致命的エラー） | 図を表示せず、ファイルごとのエラー一覧を表示する |

#### 5.2.5 処理系（致命的）

| ID | 事象 |
| --- | --- |
| E401 | **読み込み済みの全プロジェクトの合計タスク件数**が処理上限（**20,000 件**）を超える。ファイル名昇順で検証し、合計が上限を超えることになるファイルを拒否する（機能仕様書 3.5 参照） |
| E402 | 読み込みファイル数（読み込み済み ＋ 今回の選択分）が上限（**100 個**）を超える。ファイル名昇順で 100 個目までを採用し、以降のファイルを拒否する（機能仕様書 3.5 参照）。**ステージ [0]、ファイル内容の読み込み前に検証する** |
| E403 | 予期しない実行時エラー |
| E404 | ファイルサイズが上限（**10MB**）を超えた。当該ファイルのみを拒否する。**ステージ [0]、ファイル内容の読み込み前に検証する** |
| E405 | 1 タスクあたりの担当者数が上限（**20 名**）を超えた |
| E406 | 1 フィールドの文字数が上限（タスク名 **200 文字**、メモ欄 **5,000 文字**）を超えた |
| E407 | AOA 変換後のイベント・矢線数が上限を超えた（具体的な上限値は **【未定】**） |
| E408 | 描画処理が一定時間内に完了しない（具体的な時間は **【未定】**）。処理を中断する |
