## 6. セキュリティ設計

### 6.1 方針

CSV から読み込む文字列（タスク名、担当者名、ファイル名、タスク ID 等）は、外部から与えられる**信頼できない入力**として扱う。これらは画面（矢線ラベル、凡例パネル、エラーメッセージ等）に表示されるため、XSS（クロスサイトスクリプティング）等のリスクに対して**多層防御**を行う。**いずれか一層が破られても被害が拡大しないよう**、独立した複数の防御層を設ける。説明文は画面に表示しない（機能仕様書 3.3 参照）ため対象外とする。

### 6.2 防御層

| 層 | 目的 | 概要 |
| --- | --- | --- |
| 入力の無害化 | CSV 由来の文字列が HTML／SVG として解釈される余地をなくす | CSV 由来の文字列は常にテキストとして扱い、HTML／属性の構文として解釈されうる形では出力しない。具体的な実装手段（使用する DOM API、属性値の制限方法等）は本書の対象外とし、別途定める |
| リンク化の禁止 | 外部への遷移経路そのものを作らない | CSV 由来の文字列（タスク名等）はリンク化せず、**常にプレーンテキストとして表示する。** リンク（`<a>` 要素）を生成する機能は持たない |
| イベントハンドラの統一 | HTML 属性経由でのスクリプト実行を防ぐ | スクリプトの実行は JavaScript による動的なイベント登録に限定し、HTML のインラインイベント属性（`onclick` 等）は使用しない。これは CSP（後述）が正しく機能するための前提でもある |
| CSP（Content Security Policy） | 万一上記が回避されても、注入されたスクリプトを実行させない。実行された場合でも外部への情報送信を防ぐ | `default-src 'none'` を土台とする。`script-src` は `'unsafe-inline'` を使用せず、ビルド後の実際のインラインスクリプトのハッシュ値（`'sha256-...'`）のみを許可する（6.3 参照）。`style-src` は `'unsafe-inline'` を許可する。`connect-src` は許可せず、完全オフライン要件（機能仕様書 2 章参照）を裏付ける |

これらは独立した層であり、いずれか 1 つが突破されても、他の層が被害の拡大（任意コード実行、外部への情報送信等）を防ぐことを意図する。実装上の具体的な手段・理由づけは本書の対象外とし、別途定める。

### 6.3 CSP の位置づけ

配布形態が HTML ファイル単体となる場合、CSP は HTTP レスポンスヘッダーではなく `<meta>` タグで指定する必要がある。**`<meta>` タグによる配信では `frame-ancestors` ディレクティブは効力を持たず、他サイトへの埋め込み（クリックジャッキング等）の防止は保証できない。** これを保証する必要がある場合は、HTTP レスポンスヘッダーを設定可能な配布形態への変更が必要になるが、その判断は本書の対象外とする。

**また、CSP の `<meta>` タグは許可対象のインラインスクリプトよりも必ず前に出力しなければならない。** `<meta>` による CSP は、そのタグより前に解析・実行された要素には遡って適用されないためである（具体的な配置方法は別途定める）。

CSP は他の防御層が突破された場合の**最終防御線**であり、外部への不正な情報送信（データの持ち出し）を防ぐことを主目的とする。完全オフライン動作要件（機能仕様書 2 章参照）とも整合する。

**ディレクティブ全文は以下の通り確定する。**（`script-src` のハッシュ値は例。実際の値はビルドごとに算出する）

```
default-src 'none';
script-src 'sha256-<ビルド時に算出したインラインスクリプトのハッシュ値>';
style-src 'unsafe-inline';
connect-src 'none';
font-src 'none';
frame-src 'none';
object-src 'none';
media-src 'none';
img-src 'none';
base-uri 'none';
form-action 'none';
frame-ancestors 'none';
```

| ディレクティブ | 値 | 根拠 |
| --- | --- | --- |
| `default-src` | `'none'` | 明示的に許可した以外はすべて拒否する土台 |
| `script-src` | `'sha256-...'`（ビルド時算出） | 単一 HTML への全インライン展開のため許可が必要だが、`'unsafe-inline'` は注入されたスクリプトも実行してしまうため使用しない。ビルド後の正規スクリプトのハッシュ値のみを許可する（6.2「イベントハンドラの統一」が前提） |
| `style-src` | `'unsafe-inline'` | 単一 HTML への全インライン展開のため必須。CSS 注入は `img-src`／`connect-src` の `'none'` により外部への持ち出し経路が塞がれているため、スクリプトほど厳格なハッシュ化は行わない |
| `connect-src` | `'none'` | 完全オフライン要件（機能仕様書 2 章参照）。外部通信を一切行わない |
| `font-src` | `'none'` | OS 標準フォントのみを使用し、Web フォントを読み込まない（機能仕様書 2.1 参照） |
| `frame-src` | `'none'` | iframe 等の埋め込みコンテンツを使用しない（UI・UX仕様書 1.4 参照） |
| `object-src` / `media-src` | `'none'` | プラグイン・音声・動画を使用しない |
| `img-src` | `'none'` | ファビコン等の画像を一切使用しない |
| `base-uri` | `'none'` | `<base>` タグによる相対 URL 基点の書き換えを禁止する |
| `form-action` | `'none'` | フォーム送信を行わない（ファイル読み込みは `<input type="file">` と JavaScript のみで完結する） |
| `frame-ancestors` | `'none'` | **`<meta>` 配信では効力を持たない。** 埋め込み防止は保証されないことを踏まえたうえで、意図を示す宣言として記述する |

### 6.4 データの取り扱い

- CSV に由来するデータ（タスク内容、ファイル名等）は、`localStorage`・`IndexedDB`・URL（クエリパラメータ等）・コンソールログのいずれにも保存・出力しない
- 「リセット」操作（UI・UX仕様書 1.4 参照）を行った際は、メモリ上に保持しているプロジェクトデータ・エラー詳細、および生成済みの Blob URL（存在する場合）をすべて破棄する
