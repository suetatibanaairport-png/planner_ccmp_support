## 2. 単体テストの重点項目

**副作用の分離（機能仕様書 4.1）**

- CSV パース以降（ステージ [2]〜[12]）が副作用を持たない純粋関数として実装されていること。ファイル I/O（`FileReader`）・UI 通知・描画（ステージ [1]、[13]〜[14]）が別レイヤーに分離されていることをコードレビューで確認する

**CSV パーサー**

- 引用符内の改行を含むフィールド（サンプル 44〜46 行目相当）
- `""` によるエスケープを含むフィールド（サンプル 47 行目相当）
- BOM の有無
- CRLF / LF
- 末尾の空行

**後続タスク抽出**

- 記載なし／1 件／複数件
- 前後の空白、区切り直後の空白
- 説明文中の任意の位置にある場合
- 存在しない ID の参照
- 自己参照、重複記載
- `後続タスク:` が 1 タスクの説明欄に複数回出現した場合にエラー（E204）となること
- 定期的＝はい のタスクが除外された（W312）場合、そのタスク ID を先行・後続いずれかに持つ辺が W301 と同様に無視されること。辺の先で参照されていた相手タスク自体は除外されないこと

**営業日数算出**

- 月〜金（5 営業日）
- 金〜月（2 営業日）
- 土〜日（0 営業日）
- 同一日（1 営業日）
- 月をまたぐ期間、年をまたぐ期間
- 開始日 > 期限日
- 開始日・期限日のいずれかが空欄の場合、所要日数が 3 営業日として仮置きされること（W304/W305）
- 開始日 > 期限日の場合も、開始日・期限日が空欄の場合と同様に 3 営業日の仮置きとなること（W306）

**休日設定ファイルの読み込み（機能仕様書 3.7）**

- 既定ファイル [japan_holidays_2025FY-2027FY.csv](../data/japan_holidays_2025FY-2027FY.csv) に列挙された祝日が非営業日として算出に反映されること
- ファイルに記載のない日付（対象期間外）は祝日として扱われず、土曜・日曜のみが非営業日として判定されること
- 既定ファイルの対象期間（2025 年度〜2027 年度）より前・より後の日付を含むタスクでも、土曜・日曜が非営業日として正しく外挿されること（祝日は考慮されないこと）
- `YYYY-MM-DD` 形式（ハイフン区切り）で正しく日付が解釈されること（タスク CSV の `YYYY/MM/DD` 形式との混同がないこと）
- 名称列の値によらず、日付列のみで非営業日が判定されること
- フッターの「休日設定ファイル」ボタンから別のファイルを読み込むと、既定ファイル（またはそれ以前に読み込んだファイル）の内容が破棄され、新しいファイルの内容に置き換わること
- 日付形式が不正な行があっても、その行のみ無視して残りが読み込まれること（W313）
- 読み込んだファイルが不正な形式の場合、置き換えが行われず、それまでの内容のまま継続すること（W314）
- 休日設定ファイルを置き換えると、読み込み済みの全プロジェクトの所要日数・クリティカルパス・図の描画が再読み込みなしで再計算されること
- **ネットワークを切断した状態（`file://` で開いた状態）で、既定の休日設定ファイルの内容が正しく反映されること**（ビルド時に埋め込まれた内容が使われ、外部ファイルの動的読み込みが発生しないことを開発者ツールで確認する）

**アローダイアグラム変換**（機能仕様書 4.2、変換アルゴリズムの詳細は [詳細設計書.md](詳細設計書.md) 参照）

- 直列（A→B→C）
- 分岐（A→B, A→C）
- 合流（A→C, B→C）：合流イベントの生成
- 交差依存（A→C, A→D, B→D）：ダミーが必要となる典型ケース
- 同一先行集合を持つ複数タスクの開始イベント共有
- 並行作業の分離
- ダミー矢線の縮約の前後比較
- イベント番号が全矢線で `i < j` を満たすこと（不変条件として全テストで検証）
- 複数の独立プロジェクト（非連結グラフ）
- 複数担当タスクが担当者数分のエッジに分割され、0 営業日のダミー矢線で合流すること
- 孤立タスクが独立したプロジェクト（レーン）としてまとめられること
- 循環依存（A→B→C→A 等）が E203 として検出され、循環経路がタスク ID の順序（例：A → C → B → A）で表示されること。単なる関与タスクの集合ではなく経路として示されること
- 所要日数が仮置き（機能仕様書 3.6 参照）のタスクのエッジがジグザグの実線で描画されること
- 手動編集後の再計算（詳細設計書 10.1 の後半）が、同一の `{tasks, edges}` に対して読み込み時と同一の AOA・スケジュール・CCPM の結果を返すこと

**スケジュール計算**

- クリティカルパスが一意なケース
- クリティカルパスが複数存在するケース
- ダミーを含む経路での ES/LS
- 全タスクの `TF ≥ 0` であること（不変条件）

**共通時間軸への変換（機能仕様書 4.1.5）**

- プロジェクトの基準日が、先行タスクを持たないタスクのうち有効な開始日を持つものの最早日になること
- 先行タスクを持たないタスクの開始日がすべて欠落している場合、プロジェクト内の他タスクの最早の有効な開始日にフォールバックすること
- プロジェクト内（孤立タスクの独立プロジェクトを含む）に有効な開始日を持つタスクが 1 件もない場合、警告（W315）が表示され、オフセット 0 で継続すること
- 複数プロジェクトのオフセットが、全プロジェクトの基準日のうち最も早いものを原点として算出されること
- **読み込んだ全プロジェクトに有効な開始日が 1 件もない場合、実日付に基づかない仮想的な原点となり、全プロジェクトのオフセットが 0 になること（循環参照が発生しないこと）**
- 基準日（または全体の原点）が土曜・日曜・祝日にあたる場合、直後の最初の営業日に繰り下げて換算されること
- 後続タスクの表示位置が ES（依存関係と所要日数から算出した値）に従い、その CSV 記載の開始日とは独立していること（両者が意図的に異なりうるケースを含む）

**CCPM**

- 合流バッファ候補が検出されるケース
- 合流はあるが両方がクリティカルチェーン上のケース（候補としない）
- 合流のないケース（候補 0 件）

**複数ファイル読み込み（`workspace/`）**

- 2 ファイルで同一のタスク ID が使われている場合、エラー（E206）となり後から読み込もうとしたファイルの追加が拒否されること（該当ファイル名とタスク ID が示されること）
- 2 ファイルのタスク ID がすべて異なる場合、それぞれ独立したプロジェクトとして正しく処理されること（E201 が誤検知されないこと）
- 内容が完全に同一の 2 ファイルを読み込んだ場合、全タスクの ID が重複するため E206 として検出・拒否されること
- 一方のファイルが致命的エラー（例：必須列欠落）でも、他方は正常に描画されること
- 同一人物（同一氏名）がファイルをまたいで存在する場合、同一色が割り当てられること
- フッターの「担当者凡例」ボタンから凡例パネルが開閉でき、担当者名と割り当てられた色の組み合わせが一覧表示されること（「未アサイン」の色を含む）
- ファイルの追加・解除により色が再生成された場合、凡例パネルの内容も追従して更新されること
- 「ファイルを開く」操作の繰り返しによる追加読み込みで、既存プロジェクトの状態が変化しないこと
- 「リセット」操作で読み込み済みの全プロジェクトが解除されること
- 定期的＝はい のタスクが含まれるファイルを読み込んだ場合、エラーとせず当該タスクが除外されること（W312）
- 同一ファイル名のファイルを重複して読み込もうとした場合、エラー（E205）となり追加が拒否されること
- 複数プロジェクトが、各プロジェクトの基準日（機能仕様書 4.1.5 参照）順にレーン表示されること
- 複数プロジェクトを横断してリソース競合（担当者の掛け持ち）が検出されること
- 読み込み済みの全プロジェクトの合計タスク件数が上限（20,000 件）を超える場合、ファイル名昇順で合計が上限を超えることになるファイルのみが拒否（E401）され、それ以前のファイルは正常に追加されること
- 読み込みファイル数（読み込み済み＋今回の選択分）が上限（100 個）を超える場合、ファイル名昇順で 100 個目までが採用され、以降のファイルのみが拒否（E402）されること。全体が中止されないこと。**`FileReader` による内容の読み込みが行われる前に判定されること**
- ファイルサイズが上限（10MB）を超えた場合にエラー（E404）となること。**`File.size` により、`FileReader` による内容の読み込みが行われる前に判定されること**
- 1 タスクあたりの担当者数が上限（20 名）を超えた場合にエラー（E405）となること
- タスク名（200 文字超）・説明欄（5,000 文字超）が上限を超えた場合にエラー（E406）となること
- 一度に複数ファイルを選択した場合、**ファイル名の昇順**に 1 ファイルずつ処理されること（OS のファイル選択ダイアログでの選択順に依存しないこと）。1 ファイルずつ繰り返し読み込んだ場合と結果が一致すること
- 同一選択内の 2 ファイルが同名、または同一タスク ID で重複する場合、ファイル名昇順で後のファイルが拒否され、先のファイルは正常に追加されること
- 選択した複数ファイルのうち一部が失敗しても、既存の読み込み済みプロジェクトの状態が変化せず、成功したファイルの追加が取り消されないこと

**エラー表示**

- 致命的エラーが単発（1 件）の場合に `alert` で表示されること
- 複数件、または複数ファイルにまたがる場合、フッター左端の「エラー表示」ボタンからスクロール可能なパネルが展開されること
- パネル内の各エラーが、1 行目「`<ファイル名> - <ステージ名>`」、2 行目以降にエラー内容という形式で表示されること
- ステージ名が、`E1xx`＝「ファイル・パース」、`E2xx`＝「データ整合性」、`E4xx`＝「処理」に対応していること
- 「エラー表示」ボタンの右側に、エラー件数が丸バッジで表示されること。エラーが 0 件の場合はバッジが表示されないこと
- 主要な操作（ファイルを開く、リセット、休日設定ファイルの読み込み）を行うと、それぞれ操作結果が通知されること

**依存関係の手動編集（`edit/`。機能仕様書 4.3）**

- 先行タスクの追加が、先行側タスクの後続タスクとして 1 辺追加されること
- 後続タスクの追加が、対象タスクの後続タスクとして 1 辺追加されること
- 先行・後続の一覧からの削除が、対応する 1 辺のみを削除すること
- 循環を生じる追加が拒否されること（追加前後で `edges` が不変であること）。削除では循環チェックを行わないこと
- 既存の後続タスクの重複追加、自己参照が拒否されること
- 変更タスクの差分が、読み込み時の `edges` と現在の `edges` の後続 ID 集合の比較で算出されること。元に戻す／やり直しで元の状態に一致した場合、そのタスクが差分から外れること
- 出力 CSV 文字列が 2 列（タスク名／`後続タスク：<ID>,<ID>`）であること。ID 区切りは半角カンマ、コロンは全角。カンマを含む 2 列目が引用符で囲まれること。後続を全削除したタスクは `後続タスク：`（値なし）になること
- 定期的タスク宛ての辺が編集レイヤ（前半出力の `edges`）で保持され、出力 CSV から欠落しないこと
- 元に戻す／やり直しがプロジェクト単位で独立しており、いずれも全履歴を遡れること。新規操作でやり直しスタックが空になること

**プロジェクト名ラベル（機能仕様書 3.5.4）**

- 各プロジェクトの先頭タスクの上部・左詰めにファイル名（拡張子を除く）が表示されること
- 孤立タスクの独立プロジェクトにはプロジェクト名が表示されないこと

**セキュリティ（セキュリティ仕様書.md 6 章・詳細設計書.md 7 章）**

- タスク名等に `<script>` や `<img onerror=...>` 等の HTML タグを含めても、タグとして解釈されず文字として表示されること
- タスク名等に `"` を含めても、属性値からエスケープできないこと
- タスク名等に URL 文字列（`https://...` 等）を含めても、`<a>` 要素が生成されず、リンク化されずにプレーンテキストとして表示されること
- 配布物のソースコードに `innerHTML`・`outerHTML`・`insertAdjacentHTML`・`document.write` が使用されていないこと（CSV 由来の文字列を扱う箇所に限らず、コードレビューで確認する）
- コードレビューで、CSV 由来の文字列が `href`／`xlink:href`／`style`／`on*` 系の属性値、または属性名・要素名として使用されていないことを確認する（`setAttribute` の呼び出し箇所を網羅的に確認する）
- 配布物に CSP の `<meta>` タグが含まれ、機能仕様書 6.3 のディレクティブ全文と一致していること
- CSP の `<meta>` タグが `<head>` の先頭付近、かつすべての `<script>` より前に出力されていること（HTML ソースを確認する）
- `script-src` が `'unsafe-inline'` ではなく、ビルド後のインラインスクリプトのハッシュ値になっていること
- 配布物の HTML に `onclick` 等のインラインイベント属性が存在せず、すべて `addEventListener` で登録されていること
- 開発者ツールのコンソールで、CSP 違反（ハッシュ不一致によるスクリプトブロック等）が想定通り発生することを、意図的にインラインスクリプトを挿入して確認する
- 操作中に `localStorage`・`IndexedDB`・URL・コンソールログへ CSV 由来のデータが一切出力されないこと（開発者ツールで確認）
- 「リセット」操作後、メモリ上のプロジェクトデータ・エラー詳細・生成済み Blob URL（存在する場合）が破棄されていること
- いかなる通信も発生しないこと（ブラウザの開発者ツールで確認）

## 4. 手動確認項目

- Windows / macOS それぞれの Edge・Chrome で表示が崩れないこと
- **ネットワークを切断した状態で全機能が動作すること**（開発者ツールの Network タブで外部リクエストが 0 件であることを確認）

- 担当者ごとの色分けが判別可能であること、かつ複数プロジェクトで同一人物の色が揃っていること
- 「ファイルを開く」ボタンで複数ファイルを一度に選択して読み込めること、および操作を繰り返して追加読み込みできること

- ヘッダーにアプリケーション名が表示され、フッターの著作権表示・ライセンス種別・サードパーティライセンスが横並びで表示されること（ライセンス全文は表示されないこと）
- フッター左端に「担当者凡例」「依存関係編集」「エラー表示」「休日設定ファイル」の順でボタンが配置されていること
- ヘッダー・フッターがそれぞれ 1 行に収まっており、メイン領域が最大限確保されていること
- メイン領域にズーム用の拡大・縮小ボタンが表示され、操作できること
- メイン領域の各プロジェクトに、先頭タスクの上部・左詰めでプロジェクト名（ファイル名）が表示されること。孤立タスクの独立プロジェクトには表示されないこと
- フッター左端の「依存関係編集」ボタンでペインが開閉できること（既定は折りたたみ）
- ペイン 1 行目のリストボックスで対象プロジェクトを切り替えると、表と元に戻す／やり直しの履歴が入れ替わること

- 後続タスク一覧が読み込み時と異なるタスク名が暗い赤（`#8B0000`）で表示されること
- 循環・重複・自己参照の操作、編集内容の破棄、「グラフを更新」の初回押下で、それぞれメッセージウィンドウが表示されること（初回通知は 2 回目以降表示されないこと）

- 「元に戻す」「やり直し」がボタン操作で機能すること
