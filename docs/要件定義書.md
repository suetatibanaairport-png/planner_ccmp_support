## 1. 背景・課題

Microsoft 365 Planner の無料プランには、タスク間の先行・後続関係（依存関係）を保持する機能がない。そのため、Planner 単体では以下ができない。

- タスクの依存関係を可視化したアローダイアグラム（PERT図）の作成
- 依存関係にもとづくクリティカルパスの算出
- CCPM（クリティカルチェーンプロジェクトマネジメント）実践に必要な、合流バッファ挿入候補の検出

一方、タスクの説明欄に規約に沿って後続タスク ID を記載すれば、依存関係の情報自体は Planner 上に保持できる。この記法を解釈し、可視化・分析を行うツールが必要である。

## 2. 目的・ゴール

Microsoft 365 Planner が出力する CSV を入力として、以下を実現するスタンドアロンのブラウザアプリケーションを提供する。

1. タスクの説明欄に記載された後続タスク ID から依存関係グラフを構築する
2. 依存関係グラフをアローダイアグラム（AOA 形式）に変換して描画する
3. クリティカルパス（クリティカルチェーン）を算出する
4. CCPM における合流バッファの挿入候補を検出する
5. 複数の CSV（複数プロジェクト）を同時に読み込み、横断して確認できるようにする

機能要件の詳細は [機能仕様書.md](機能仕様書.md) 1〜4章を参照。

## 3. 想定利用者・利用シーン

- Microsoft 365 Planner でタスク管理を行っており、CCPM の考え方でスケジュールを分析したい個人・小規模チームの利用者
- Planner から CSV をエクスポートし、本ツールに読み込ませて図を確認する、という単発〜都度の利用を想定する（常駐サービスではない）
- 想定規模は個人・小規模利用であり、大規模組織での一斉導入・SaaS 提供は想定しない（[機能仕様書.md](機能仕様書.md) 2.1 参照）

## 4. 要求事項（業務要件）

| # | 要求 | 対応する機能仕様 |
| --- | --- | --- |
| 1 | Planner の CSV をそのまま読み込めること（Planner 側の追加設定・エクスポート形式の変更を要求しない） | 機能仕様書 3章 |
| 2 | 依存関係の記法は Planner の標準機能（説明欄への記載）のみで完結し、追加のツール・アドインを必要としないこと | 機能仕様書 3.3 |
| 3 | 複数プロジェクト（複数 CSV）を一度に確認でき、担当者の掛け持ち状況が横断的にわかること | 機能仕様書 3.5, 4.1.3 |
| 4 | データ入力の誤り（列不足・ID 重複・循環参照等）を検出し、誤った図を無警告で見せないこと | 機能仕様書 5章 |
| 5 | クリティカルパスだけでなく、CCPM の合流バッファ候補まで機械的に算出できること | 機能仕様書 4.1.4 |

## 5. 非機能要件

### 5.1 セキュリティ

- **入力データ（CSV）は信頼できない外部入力として扱う。** タスク名・説明欄等に HTML/スクリプトの断片や URL が含まれていても、実行・リンク化されず単なる文字として表示されること（機能仕様書 6章、詳細設計書 7章）
- DOM 書き込みは安全な API 経由のみに限定し、機械的に強制されること（開発ガイド.md「静的チェック」参照）
- 配布物は Content Security Policy により、想定外のスクリプト実行を多重に防止すること（機能仕様書 6.3）
- リポジトリへの秘密情報（API キー等）の混入を機械的に検出する仕組みを持つこと（開発ガイド.md 参照）
- 依存パッケージの既知の脆弱性を継続的に検知し、更新に追従できること（開発ガイド.md 参照）

### 5.2 オフライン動作・可搬性

- **実行時にネットワーク通信を一切行わないこと。** 外部 API・CDN・テレメトリ送信のいずれも不可（機能仕様書 2.1）
- 導入操作なしに使えること。利用者はファイルをダウンロードして開くだけで動作すること（開発ガイド.md「配布物（dist/）」参照）
- 対象 OS・ブラウザを問わず、追加ランタイムのインストールを要求しないこと（機能仕様書 2章）
- **配布物（ビルド後の単一 HTML ファイル）のファイル名は `Planner_ccmp_support.html` に固定すること（2026-08-08 決定）**

### 5.3 品質・テスト容易性

- 依存関係グラフ構築・所要日数算出・クリティカルパス算出等の中核ロジックは、副作用を持たない純粋関数として実装し、自動テストで継続的に検証できること（機能仕様書 4.1、テスト仕様書 1〜2章）
- テストが実際に不具合を検出できることを担保する仕組み（ミューテーション確認等）を運用上考慮すること（テスト仕様書、CLAUDE.md 参照）
- コード品質（静的解析・型検査・整形）を人手のレビューだけに依存せず、機械的に担保すること（開発ガイド.md「静的チェック」参照）

### 5.4 運用・保守性

- 上記の品質担保（静的解析・テスト・セキュリティスキャン）は、コミット時およびリポジトリへの反映時の両方で自動的に実行され、うっかりした見落としが本流に混入しないこと（開発ガイド.md「コミット時の自動実行」「CI」参照）
- ドキュメントおよびコードのコメントは日本語を主体とすること（CLAUDE.md 参照）
- 「何が要件か」「何を実装するか」「どう実装するか」を文書として分離し、後から参照・検証できること（本書、機能仕様書.md、詳細設計書.md の役割分担）

### 5.5 性能

- 想定するデータ規模：**ファイル数は最大 100 ファイル、1 ファイルあたりのタスク数は 100〜200 件を想定する（2026-08-08 決定）**
- エラー仕様書.md の E401（合計タスク件数上限）・E402（ファイル数上限）は、この性能目標に合わせ E401 を 20,000 件、E402 を 100 個に改定済み（機能仕様書.md・エラー仕様書.md・テスト仕様書.md に 2026-08-08 反映）

## 6. 制約条件

- Planner 無料プランには依存関係を保持する機能がないため、依存関係はタスク説明欄への規約準拠の記載に依存する（2章参照）。この規約から外れた記載は解釈できない
- ブラウザの `file://` スキームでの動作を前提とするため、ES モジュールの動的読み込みや `fetch` によるファイル取得はできない（詳細設計書 1章参照）。この制約が、単一 HTML 配布・`FileReader` によるファイル入力という実現方式の前提となっている
- Planner の日本語 UI 出力のみを対象とし、英語ロケール出力には対応しない（機能仕様書 3.2）
- CSP を `<meta>` タグで配布する制約上、`frame-ancestors` 等 HTTP レスポンスヘッダーでしか効かないディレクティブによる防御は実現できない（機能仕様書 6章、開発ガイド.md 参照）

## 7. 対象外（スコープ外）

機能面のスコープ外は [機能仕様書.md](機能仕様書.md) 1.3 に詳細がある。要求事項レベルでは以下を対象外とする。

- Planner / Microsoft Graph API との直接連携、Planner への書き戻し（オフライン動作要件と矛盾するため）
- 複数プロジェクト間のタスク内容そのものの比較（データ不整合検出とは別の要求であり、対象としない）
- モバイル・タブレット向け利用、複数ユーザーでの共同編集・サーバー側データ保存

**将来対応（現バージョンではスコープ外）**

- 進捗実績にもとづくバッファ消費率の管理（フィーバーチャート等）：**バージョン2で実装予定（2026-08-08 決定）**

## 8. 用語

| 用語 | 意味 |
| --- | --- |
| AOA | Activity On Arrow。タスクを矢線、時点をイベント（節点）として表すアローダイアグラム形式 |
| CCPM | クリティカルチェーンプロジェクトマネジメント。クリティカルチェーンにバッファを設けて管理する手法 |
| 合流バッファ | クリティカルチェーンに非クリティカルな作業が合流する箇所に設ける、遅延吸収用の余裕期間 |
| プロジェクト | 本アプリでは 1 CSV ファイル＝1 プロジェクトとして扱う（機能仕様書 3.5 参照。Planner 上のプランとは 1:1 とは限らない） |
