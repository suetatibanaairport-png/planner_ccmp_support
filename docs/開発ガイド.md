# 開発ガイド

本アプリケーションは Microsoft 365 Planner が出力するタスクリスト（CSV）をもとに、簡易的なアローダイアグラム（PERT図）を作成するものです。
また、クリティカルチェーンプロジェクトマネジメント（CCPM）用に合流バッファ候補検出とクリティカルチェーン算出を行います。

機能要件・画面構成・データ処理仕様等の詳細は [機能仕様書.md](機能仕様書.md)、実装方式の詳細は [詳細設計書.md](詳細設計書.md)、テスト方針・テストデータの詳細は [テスト仕様書.md](テスト仕様書.md) を参照してください。本ガイドでは開発上の方針のみを記します。

## 技術構成

[詳細設計書.md](詳細設計書.md) 2 章の技術構成案に沿って、以下の構成で実装している。

| 領域 | 採用技術 |
| --- | --- |
| 言語 | TypeScript（`strict` 有効） |
| ビルド | Vite + `vite-plugin-singlefile`（単一 HTML ファイルへインライン化） |
| UI | フレームワークなし。素の DOM 操作（`src/security/dom.ts` を唯一の窓口とする） |
| CSV パース | 自前実装（RFC 4180 準拠、外部ライブラリ不使用。`src/csv/parseCsv.ts`） |
| 図の描画 | SVG の直接生成 |
| レイアウト計算 | 自前実装 |
| 日付処理 | 標準の `Date`（UTC 基準） |
| 単体テスト | Vitest |
| 静的解析・整形 | ESLint / Prettier（下記「静的チェック」参照） |

完全オフライン動作（[機能仕様書.md](機能仕様書.md) 2 章参照）のため、すべての依存ライブラリはビルド時にバンドルし、**配布物（ビルド後の HTML）が実行時に外部リソースを参照することはない。** これは開発・CI 時に `npm install`（`npm ci`）で npm レジストリからパッケージを取得することを妨げるものではない（オフライン要件は配布物の実行時挙動に対するものであり、開発・ビルド環境のネットワーク利用とは区別する）。

## 静的チェック

以下を確認する。Lint・型チェック・整形チェック・テスト・ビルドは下記の pre-commit フックと CI により自動化されているが、**それに頼って確認を省略してよいという意味ではない。**

- 静的解析には ESLint を使用する（`npm run lint`）。コードの品質を確認する
  - `no-restricted-syntax` により、`innerHTML`/`outerHTML`/`insertAdjacentHTML`/`document.write` を `src/security/dom.ts` 以外で使用していないかを機械的に検出する（機能仕様書 6.2 / 詳細設計書 7.1 の DOM API 使用ルールに対応）
- 型チェックには TypeScript を使用する（`npm run typecheck`）
- コード整形には Prettier を使用する（`npm run format` で整形、`npm run format:check` で確認のみ）。対象は `src/` 等のソースコードのみとし、仕様書等の Markdown ドキュメントは対象外とする（`.prettierignore` 参照）
- インターネットに公開してはならない情報（個人情報、内部システムの機微情報等）が含まれていないかを確認する（**これは自動化されていない。都度手動で確認すること**）

### コミット時の自動実行（pre-commit フック）

[Husky](https://typicode.github.io/husky/) により、`git commit` のたびに [.husky/pre-commit](../.husky/pre-commit) が以下を順に実行し、**いずれかが失敗するとコミットがブロックされる。**

1. `npm run lint`
2. `npm run typecheck`
3. `npm run format:check`
4. `npm test`
5. `npm run build`

`npm install`（初回セットアップ時）で `prepare` スクリプトが自動的に Git フックを有効化する。緊急時にフックを一時的に回避する場合は `git commit --no-verify` を使うが、通常運用では使用しないこと。

### CI（GitHub Actions）

pre-commit フックと同じ内容を、[.github/workflows/ci.yml](../.github/workflows/ci.yml) により `main` への push・Pull Request のたびにも自動実行する。ローカルの pre-commit フックを回避した場合や、フック導入前の環境からの push を防ぐための最終防御である。
