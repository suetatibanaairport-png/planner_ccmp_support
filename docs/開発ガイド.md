# 開発ガイド

本アプリケーションは Microsoft 365 Planner が出力するタスクリスト（CSV）をもとに、簡易的なアローダイアグラム（PERT図）を作成するものです。
また、クリティカルチェーンプロジェクトマネジメント（CCPM）用に合流バッファ候補検出とクリティカルチェーン算出を行います。

背景・目的・要求事項の詳細は [要件定義書.md](要件定義書.md)、機能要件・データ処理仕様等の詳細は [機能仕様書.md](機能仕様書.md)、画面構成・表示要件の詳細は [UI・UX仕様書.md](UI・UX仕様書.md)、多層防御・CSP の詳細は [セキュリティ仕様書.md](セキュリティ仕様書.md)、エラー・警告コードの詳細は [エラー仕様書.md](エラー仕様書.md)、実装方式の詳細は [詳細設計書.md](詳細設計書.md)、テスト方針・テストデータの詳細は [テスト仕様書.md](テスト仕様書.md) を参照してください。本ガイドでは開発上の方針のみを記します。

## 技術構成

[詳細設計書.md](詳細設計書.md) 2 章の技術構成に沿って、以下の構成で実装している。

| 領域 | 採用技術 |
| --- | --- |
| 言語 | TypeScript（`strict` 有効） |
| ビルド | Vite + `vite-plugin-singlefile`（単一 HTML ファイルへインライン化） |
| UI | フレームワークなし。素の DOM 操作（`src/security/dom.ts` を唯一の窓口とする） |
| CSV パース | [PapaParse](https://www.papaparse.com/)（MIT、実行時依存0件。`src/csv/parseCsv.ts`でラップする） |
| 図の描画 | SVG の直接生成 |
| レイアウト計算 | 自前実装（汎用グラフレイアウトライブラリは AOA 座標のピン留め要件と相性が悪いため。詳細設計書 2 章参照） |
| 日付処理 | 標準の `Date`（UTC 基準） |
| 単体テスト | Vitest |
| 静的解析・整形 | ESLint / Prettier（下記「静的チェック」参照） |

ESLint・TypeScript・Vite・Prettier のツール設定ファイルは `config/` にまとめている（`package.json` の `npm run` スクリプトが内部で参照するため、通常の利用では意識する必要はない）。

完全オフライン動作（[機能仕様書.md](機能仕様書.md) 2 章参照）のため、すべての依存ライブラリはビルド時にバンドルし、**配布物（ビルド後の HTML）が実行時に外部リソースを参照することはない。** これは開発・CI 時に `npm install`（`npm ci`）で npm レジストリからパッケージを取得することを妨げるものではない（オフライン要件は配布物の実行時挙動に対するものであり、開発・ビルド環境のネットワーク利用とは区別する）。

新規に実行時依存を追加する場合は、この完全オフライン要件（ビルド時バンドル・実行時外部通信なし）を満たせるパッケージに限る。ライセンスは本プロジェクト（MIT）と適合すること（コピーレフト系ライセンスは配布方針上避ける）。

**サードパーティライセンス表示：** PapaParse（MIT）がバンドルされる最初の実行時依存であり、機能仕様書 7.3「サードパーティライセンス」の要求（バンドルする依存ライブラリの著作権表示を配布物内に含める）に対応し、フッターに `Third-party licenses: PapaParse (MIT License)` と表示する（`src/ui/App.ts`）。依存が PapaParse 1件のみのため、7.2 の自社ライセンス表示と同様に名称・ライセンス種別のみの静的な文字列とし、ビルド時の自動収集は行わない。依存ライブラリが増える場合は、この静的表示が実態と乖離しないよう都度見直すこと。

## 配布物（dist/）

`npm run build` の成果物（単一 HTML ファイル `dist/Planner_ccmp_support.html`）は **リポジトリにコミットして配布する。** 利用者はビルドせずに `dist/Planner_ccmp_support.html` をダウンロードしてブラウザで開くだけで使用できる。配布物のファイル名は固定名とする（リネームの仕組みは詳細設計書.md 1章参照）。

そのため `dist/` は `.gitignore` の対象外とし、下記の pre-commit フックがコミットのたびに再ビルドして `git add dist` することで、**ソースコードと `dist/` の内容が常に一致する状態を保つ。** `git commit --no-verify` でフックを回避した場合は `dist/` が古いまま残るため、その場合は手動で `npm run build && git add dist` を行うこと。

## 静的チェック

以下を確認する。Lint・型チェック・整形チェック・テスト・ビルドは下記の pre-commit フックと CI により自動化されているが、**それに頼って確認を省略してよいという意味ではない。**

- 静的解析には ESLint を使用する（`npm run lint`）。コードの品質を確認する
  - `no-restricted-syntax` により、`innerHTML`/`outerHTML`/`insertAdjacentHTML`/`document.write` を `src/security/dom.ts` 以外で使用していないかを機械的に検出する（機能仕様書 6.2 / 詳細設計書 7.1 の DOM API 使用ルールに対応）
- 型チェックには TypeScript を使用する（`npm run typecheck`）
- コード整形には Prettier を使用する（`npm run format` で整形、`npm run format:check` で確認のみ）。対象は `src/` 等のソースコードのみとし、仕様書等の Markdown ドキュメントは対象外とする（`config/.prettierignore` 参照）
- シークレット（API キー・トークン等）の混入検出には [gitleaks](https://github.com/gitleaks/gitleaks) を使用する。事前に導入しておくこと（例: `brew install gitleaks`、または[リリースページ](https://github.com/gitleaks/gitleaks/releases)からバイナリを取得）
- 依存パッケージの脆弱性検出には `npm audit --omit=dev --audit-level=high` を使用する（本番依存のみ、高深刻度以上を対象。CI でのみ実行、下記参照）。依存更新の追従は [Dependabot](../.github/dependabot.yml)（npm / GitHub Actions を毎週チェック）に任せる
- インターネットに公開してはならない情報（個人情報、内部システムの機微情報等）が含まれていないかを確認する（**これは自動化されていない。都度手動で確認すること**）

### コミット時の自動実行（pre-commit フック）

[Husky](https://typicode.github.io/husky/) により、`git commit` のたびに [.husky/pre-commit](../.husky/pre-commit) が以下を順に実行し、**いずれかが失敗するとコミットがブロックされる。**

1. `gitleaks protect --staged`（未導入の場合はここで失敗する。上記「静的チェック」参照）
2. `npm run lint`
3. `npm run typecheck`
4. `npm run format:check`
5. `npm test`
6. `npm run build`
7. `git add dist`（再ビルドした `dist/` をコミットに含める。上記「配布物（dist/）」参照）

`npm install`（初回セットアップ時）で `prepare` スクリプトが自動的に Git フックを有効化する。緊急時にフックを一時的に回避する場合は `git commit --no-verify` を使うが、通常運用では使用しないこと。

### CI（GitHub Actions）

pre-commit フックと同じ内容に加え `npm audit --omit=dev --audit-level=high` を、[.github/workflows/ci.yml](../.github/workflows/ci.yml) により `main` への push・Pull Request のたびに自動実行する（gitleaks は [gitleaks-action](https://github.com/gitleaks/gitleaks-action) でリポジトリ全履歴を対象に実行）。ローカルの pre-commit フックを回避した場合や、フック導入前の環境からの push を防ぐための最終防御である。サードパーティ Action はタグではなくコミット SHA で固定し、ジョブの権限は `contents: read` のみに限定している。
